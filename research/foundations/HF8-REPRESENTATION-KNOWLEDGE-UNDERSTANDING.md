# HF8 — Representation, Knowledge, Belief, Concept, Schema, Mental Model and Understanding

## 0. Status and question

HF7 closed with:

```text
Memory != Knowledge
Memory != Belief
Retention != Understanding
RepresentedContent != WorldTruth
```

HF8 therefore asks:

> **What is represented in a Human, what does that representation mean, when is it
> endorsed, when does it count as knowledge, how are concepts/schemas/models
> structured, and what distinguishes genuine understanding from recall,
> familiarity or externally assisted answer access?**

The round attacks these inherited simplifications:

```text
Representation = internal copy of reality
Knowledge = remembered fact
Belief = stored proposition
Concept = prototype
Schema = true prior knowledge
Mental model = every internal representation
Understanding = confidence or recall
AI gives answer = Human knows/understands
```

None survives cross-context falsification.

---

# 1. Representation is qualifier-required

`Representation` is not one primitive object.

HF8 separates at least:

```text
RepresentationalVehicle
RepresentationalContent
Referent / Target
Format / Structure
CurrentActivation
Availability
Accuracy / TruthRelation
Use / FunctionalRole
```

A neural pattern, verbal sentence, image, category prototype, motor policy and
relational model may all serve representational roles without sharing one format.

Thus:

```text
Representation_D
```

should specify what relation/function is under study.

---

# 2. Vehicle is not content

A useful foundational distinction is:

```text
Vehicle
= the physical/functional state implementing a representation

Content
= what the representation is about / carries / makes available
```

The same content can be represented through different vehicles:

```text
spoken sentence
written sentence
image
gesture
neural population state
external diagram
```

and similar vehicles can carry different contents under different conventions or
contexts.

Therefore:

```text
RepresentationalVehicle != RepresentationalContent
```

---

# 3. Content is not referent

A representation can concern:

```text
an existing object
an absent object
a future event
a fictional entity
a false proposition
a possible world
```

Therefore:

```text
RepresentationalContent != ReferentExistence
```

A Human can represent something that does not exist.

---

# 4. Representation is not truth

A representation can be:

```text
accurate
partially accurate
uncertain
counterfactual
obsolete
false
```

without ceasing to be a representation.

Thus:

```text
Representation != Truth
RepresentedContent != WorldTruth
```

HF7 false-memory evidence already forces this distinction.

---

# 5. Representation is not belief

A Human can entertain or simulate content without endorsing it.

Examples:

```text
“If gravity reversed tomorrow...”
“I can imagine X but do not believe X.”
“I remember that someone claimed P.”
```

Therefore:

```text
Represented(P) != Believes(P)
```

This is essential for reasoning about alternatives and counterfactuals.

---

# 6. Representation is not current consciousness

Representational effects can guide:

```text
priming
skill
action
category judgment
habit
```

without explicit conscious report.

Thus HF8 inherits:

```text
Representation != Experience
```

from HF2/HF7.

---

# 7. Representation is not one format

HF8 rejects a universal claim that Human representations are fundamentally:

```text
symbols only
images only
prototypes only
exemplars only
rules only
predictive models only
motor policies only
```

The correct research stance is format pluralism until specific experiments force
unification.

---

# 8. Content should be typed by role

Examples:

```text
PerceptualContent
PropositionalContent
SpatialContent
CausalContent
CategoryContent
MotorPolicyContent
AffectiveValueContent
SelfRepresentationalContent
```

HF8 does not claim these are mutually exclusive ontological species.

They are useful projections preventing category collapse.

---

# 9. Truth relations are content-specific

`True/false` fits propositions more naturally than:

```text
motor skill
image quality
prototype similarity
body schema
```

Therefore epistemic evaluation must be typed:

```text
Truth(P)
Accuracy(model, target)
Calibration(probability)
Performance(policy, task)
Fidelity(memory, event)
```

Use:

```text
EpistemicFit_D
```

rather than one universal correctness operator.

---

# 10. Knowledge cannot equal memory

HF7 showed Human memory can preserve false, obsolete or source-free content.

Therefore:

```text
Memory(P) != Knowledge(P)
```

A remembered false proposition is still memory but is not factual knowledge in the
ordinary epistemic sense.

---

# 11. Knowledge cannot equal current recall

A Human can know:

```text
how to ride a bicycle
what a word means
how to navigate a familiar environment
```

without being able to produce a verbal proposition on demand.

Thus:

```text
Knowledge != CurrentRecall
```

---

# 12. Knowledge is qualifier-required

HF8 retains at least:

```text
KnowingThat(P)
KnowingHow_D
KnowingPerson/Place/Entity
KnowingHowToFind / Access
KnowingHowToVerify
DomainCompetence
```

These overlap but should not be silently identified.

---

# 13. Knowing-that

A working operational notion:

```text
KnowingThat(H,P)
```

requires more than remembered representation of P.

HF8 does not attempt to settle the philosophical necessary-and-sufficient
conditions of propositional knowledge.

It retains minimum constraints:

```text
P must be appropriately true/accurate for the claim type
H must stand in a reliable/competent epistemic relation to P
current luck or accidental guessing is insufficient
```

but leaves justification/reliabilism/gettier-style theory open.

---

# 14. Knowing-how

Operationally:

```text
KnowingHow_D(H)
= retained capability to perform or regulate a task family under relevant
  conditions
```

It may involve explicit knowledge, but need not be exhaustively verbalizable.

Amnesia skill evidence supports:

```text
KnowingHow_D != KnowingThat(P)
```

as empirical surfaces.

---

# 15. Knowing-how is not raw performance

HF1/HF6 already established:

```text
Performance != Capability
```

Therefore:

```text
OneSuccessfulAction != KnowingHow
```

A knowing-how claim needs stability, appropriate conditions and some transfer/
reliability.

---

# 16. Knowing-that is not source recollection

Developmental/amnesia evidence shows semantic/general knowledge can exist despite
weak or absent episodic recollection of where it was learned.

Thus:

```text
KnowingThat(P) != RememberingLearningEpisode(P)
```

and:

```text
KnowledgeSourceMemory
is useful but not always required for retained semantic knowledge
```

---

# 17. But source/provenance still matters epistemically

Knowing a proposition and knowing why it should be trusted are different.

HF8 separates:

```text
ContentKnowledge
SourceKnowledge
EvidenceKnowledge
ReliabilityKnowledge
```

When acting under high stakes, provenance may become essential even if the content
is familiar.

---

# 18. Source monitoring is inferential

HF7 treated source memory as distinct from content.
HF8 adds epistemic meaning:

```text
SourceAttribution
= current judgment about where information came from
```

It is not an immutable metadata field attached to memory.

Therefore:

```text
SourceAttribution != HistoricalSource by definition
```

---

# 19. Provenance has multiple dimensions

A useful provenance profile:

```text
SourceIdentity
AcquisitionTime
TransmissionPath
SourceExpertise
SourceTrustworthiness
EvidenceType
Revision/CorrectionHistory
Independence / Correlation with other sources
```

These should not collapse into one `trusted source` bit.

---

# 20. Knowledge can exist without provenance while justified action cannot always ignore provenance

A person may correctly know a mundane fact without recalling source.

But in medicine, finance, security or law, current action may require fresh
provenance/evidence despite remembered content.

Thus:

```text
KnowledgeClaim
!= ActionAuthority
```

and:

```text
RememberedTrueContent
!= SufficientOperationalEvidence
```

---

# 21. Belief

HF8 uses a restrained working definition:

> **Belief(H,P,t) = the Human currently treats/endorses proposition or model-content
> P as sufficiently world-descriptive for relevant cognition/action at time t.**

This admits graded and context-sensitive endorsement without reducing belief to
one confidence number.

---

# 22. Belief is not memory

A Human can remember P while rejecting it now.

Therefore:

```text
Memory(P) != Belief(P)
```

HF7 already provided the simple counterexample:

```text
“I remember believing P, but I no longer believe P.”
```

---

# 23. Belief is not representation

A Human can represent alternatives that are not believed.

Thus:

```text
Represented(P) != Believed(P)
```

Belief is one relation between a Human and represented content.

---

# 24. Belief is not confidence

HF3 established confidence as a metacognitive/endorsement estimate.

HF8 retains:

```text
BeliefStatus
BeliefConfidence
EpistemicCalibration
```

separately.

A person may weakly believe P with moderate confidence, or categorically endorse P
while being miscalibrated about its truth.

Therefore:

```text
Belief != Confidence
```

---

# 25. Credence and categorical belief are different useful projections

For uncertainty-sensitive tasks, a Human may represent:

```text
Pr(P) ≈ 0.7
```

without treating `P` as categorically settled.

Thus:

```text
Credence(P) != CategoricalBelief(P)
```

HF8 does not force one reduction between them.

---

# 26. Belief can be dynamically updated

Belief-updating experiments show responses to:

```text
new evidence
correction
source reliability
explanation
memory for correction
```

Therefore belief is not a frozen stored proposition.

A working update placeholder is:

```text
BeliefState_{t+1}
= Update(BeliefState_t, Evidence_t, SourceModel_t, Memory_t, Goals_t)
```

without claiming Bayesian optimality.

---

# 27. Belief updating is not memory updating only

Correction memory predicts later belief, but remembering a correction and accepting
it are not identical.

Therefore:

```text
CorrectionRemembered != CorrectionBelieved
```

and:

```text
BeliefUpdate != MemoryUpdateOnly
```

---

# 28. Source reliability affects belief update

Recent experiments show that source expertise/trustworthiness/reliability can alter
how Human beliefs update under contradiction/correction.

Thus:

```text
EvidenceContent
and
SourceModel
```

both matter.

But:

```text
ReliableSource != AutomaticallyTrueClaim
```

Source reliability is evidence about expected accuracy, not truth by fiat.

---

# 29. Backfire is not a universal correction law

The popular model:

```text
correct misinformation
→ believer becomes more committed
```

is not a robust universal empirical law.

Measurement/reliability studies and correction experiments show many corrections
reduce false belief.

Thus:

```text
Correction != UniversalBackfire
```

Domain, prior belief, source and design matter.

---

# 30. Available knowledge may not control current belief/judgment

Illusory-truth experiments show participants can have relevant knowledge yet still
judge repeated false statements as more true under some conditions.

Thus:

```text
KnowledgeAvailable != KnowledgeUsedInJudgment
```

This reconnects directly to HF7 accessibility/retrieval.

---

# 31. Belief can conflict with known evidence

A Human may possess evidence against P but still act or judge as if P were true due
to:

```text
retrieval failure
fluency
habit
identity/value pressure
motivated reasoning
source weighting
```

HF8 does not collapse these mechanisms into `irrationality`.

---

# 32. Contradictory represented contents can coexist

A Human can retain:

```text
old belief P
new correction not-P
```

simultaneously in memory.

Current endorsement/expression can depend on retrieval context.

Therefore:

```text
StoredContradiction != ImpossibleHumanState
```

and:

```text
OneCurrentResponse != SingleUnderlyingRepresentation
```

---

# 33. Concept

HF8 uses `Concept_D` as a task/domain-relative representational structure enabling
classification, inference, prediction or generalization about a class/relation.

This is deliberately functional and plural.

It does not define concepts as one representational format.

---

# 34. Concept is not category label

Knowing the word `bird` is not identical to possessing all representations used to
classify, reason about or act toward birds.

Thus:

```text
LexicalLabel != Concept
```

and:

```text
LabelRecall != ConceptualCompetence
```

---

# 35. Prototype model

Prototype models represent categories through central tendency/summary structure.

Human concept-learning experiments show strong prototype-like generalization under
some conditions.

HF8 retains:

```text
PrototypeRepresentation
```

as one powerful model.

It rejects:

```text
Concept = Prototype always
```

---

# 36. Exemplar model

Exemplar models classify/generalize using similarity to stored individual
instances.

They can strongly fit some natural-science and category-learning datasets.

Thus:

```text
ExemplarRepresentation
```

is another viable form.

But:

```text
Concept = ExemplarSet always
```

is rejected.

---

# 37. Rule-based representation

Some category tasks permit generalization via an abstract rule that cannot be
reduced to similarity to one observed item.

Thus:

```text
RuleRepresentation
```

must remain distinct from prototype/exemplar strategy where experiments separate
them.

---

# 38. One Human can use multiple concept strategies

Prototype/exemplar/rule weighting can vary by:

```text
training coherence
category boundary
age
expertise
task demand
available memory
```

Therefore:

```text
ConceptStrategy_H,D,t
```

is often more useful than one permanent concept format.

---

# 39. Same categorization performance can hide different representations

Older and younger adults can reach comparable category-generalization performance
while formal models infer different prototype/exemplar weighting.

Therefore:

```text
SameCategoryAccuracy
!= SameRepresentationalStrategy
```

This echoes HF6's:

```text
SamePerformance != SameTransitionFunction
```

---

# 40. Concept generalization is not item recognition

A Human may generalize a category structure while having weak recognition of
individual training examples, or vice versa.

Thus:

```text
ConceptGeneralization != ExemplarRecognition
```

Generalization depends on representational organization, not item retention alone.

---

# 41. Concept is not one static object

Concept use can change with goal/context.

The features relevant to:

```text
identify bird
feed bird
avoid dangerous bird
classify evolutionary relation
```

are not identical.

Therefore HF8 allows:

```text
ConceptProjection_D
```

rather than a context-free complete essence stored once.

---

# 42. Schema

HF8 uses `Schema` for:

> **organized prior relational/structural knowledge that constrains encoding,
> interpretation, inference, retrieval and integration of new information in a
> domain.**

Examples include:

```text
restaurant script
causal disease model
spatial layout
medical knowledge structure
social-role expectations
```

---

# 43. Schema is not concept

A concept can represent one category/class relation.

A schema typically organizes multiple entities/relations/events.

Therefore:

```text
Schema != Concept
```

although concepts can participate in schemas.

---

# 44. Schema is not memory store

Schemas can affect encoding/retrieval but are not identical to all memories stored
in a domain.

Thus:

```text
Schema != MemoryDatabase
```

---

# 45. Schema can improve learning

Prior knowledge congruency/coherence can:

```text
facilitate encoding
improve later memory
support rapid integration
support generalization
```

under multiple experiments.

Therefore:

```text
SchemaBenefit
```

is real and mechanistically important.

---

# 46. Schema can also distort memory

The same organized expectations can bias reconstruction toward:

```text
expected causal coherence
congruent details
plausible but unpresented relations
```

Therefore:

```text
SchemaBenefit can coexist with SchemaBias
```

and:

```text
Schema != Truth
```

---

# 47. Schema congruence is not evidence of truth

Information fitting prior knowledge is easier to assimilate in many tasks.

But:

```text
Congruent(P, Schema)
```

only means compatibility with current structure, not that P is true.

Thus:

```text
SchemaCongruence != Veridicality
```

---

# 48. Schema can become stale

A previously useful schema may become wrong after:

```text
world change
new evidence
regime shift
domain transfer
```

Therefore robust epistemic systems need schema revision, not just schema use.

---

# 49. Mental model

HF8 uses `MentalModel` narrowly for an internal representation that preserves
relevant relational/possibility structure sufficiently to support reasoning,
simulation or prediction.

This is a theory-guided working construct.

---

# 50. Mental model is not every representation

A primed word, motor habit or simple familiarity signal need not be a mental model.

Therefore:

```text
MentalModel != AllRepresentation
```

---

# 51. Mental model is not belief set

A Human may construct a model of a possibility not believed to be actual.

Thus:

```text
MentalModel(Possibility X)
!= Belief(X is actual)
```

This makes mental models especially useful for counterfactual reasoning.

---

# 52. Mental model is not world truth

A model can omit possibilities or relations.

Mental-model reasoning theory specifically predicts errors when relevant
possibilities are not represented.

Therefore:

```text
CoherentMentalModel != Complete/TrueWorldModel
```

---

# 53. Mental-model reasoning is a strong rival, not ontology authority

Johnson-Laird-style evidence shows relational/possibility representations explain
many reasoning patterns and errors.

HF8 retains that explanatory family while refusing:

```text
All reasoning = mental-model mechanism
```

without broader comparative evidence.

---

# 54. World model

HF8 distinguishes a broad `WorldModel_D` from one local mental model.

Working definition:

```text
WorldModel_D
= organized representations supporting prediction, explanation, simulation and
  intervention over a domain
```

A Human can have multiple local models that conflict or overlap.

---

# 55. World model is not belief list

A list of propositions may not encode:

```text
causal structure
transition dynamics
counterfactual dependence
spatial relation
procedural constraint
```

Therefore:

```text
WorldModel != BeliefSet
```

although beliefs can be components.

---

# 56. World model is not complete simulator

Human models are typically compressed, partial and task-relative.

Thus:

```text
WorldModel_D
```

should declare scope and failure modes.

A useful model can be inaccurate outside its operating domain.

---

# 57. Understanding

`Understanding` is among the most overloaded HF8 terms.

HF8 rejects a scalar:

```text
Understanding = 0..100
```

as a foundation ontology.

Instead it uses an `UnderstandingProfile_D` across operational surfaces.

---

# 58. UnderstandingProfile

```text
UnderstandingProfile_D = {
  accurate recall of relevant facts,
  relational organization,
  explanation,
  prediction,
  counterfactual reasoning,
  intervention planning,
  error detection,
  transfer/generalization,
  compression / abstraction,
  boundary awareness,
  uncertainty calibration
}
```

No one surface is assumed necessary/sufficient for all forms of understanding.

---

# 59. Understanding is not recall

A Human can memorize definitions/equations while being unable to:

```text
explain why
predict novel case
transfer
identify failure condition
```

Therefore:

```text
RecallAccuracy != Understanding
```

---

# 60. Understanding is not familiarity

Repeated exposure can make a mechanism feel obvious without supporting detailed
explanation.

Thus:

```text
Familiarity != Understanding
```

---

# 61. Feeling of understanding is not demonstrated understanding

Illusion-of-explanatory-depth experiments directly establish:

```text
SelfRatedUnderstanding
can exceed
DemonstratedExplanation
```

Therefore:

```text
FeelingOfUnderstanding != DemonstratedUnderstanding
```

---

# 62. Expertise does not guarantee metacognitive understanding calibration

Experts often genuinely know more.

Yet expertise can still coexist with overconfidence about explanatory detail.

Thus:

```text
Expertise != PerfectUnderstandingCalibration
```

This prevents `expert` from becoming an infallibility label.

---

# 63. Explanation is a probe, not the definition of understanding

Asking a Human to explain a mechanism can reveal missing relations.

But:

```text
ExplanationAbility != UnderstandingTotality
```

A person may understand a motor skill without verbal explanation, or generate a
verbal explanation through memorized language without robust transfer.

---

# 64. Explanation can improve learning

Self-explanation can alter:

```text
attention
hypothesis generation
abstraction
transfer
```

under some tasks.

Therefore explanation is both:

```text
measurement/probe
and
intervention
```

analogous to HF7 retrieval.

---

# 65. Explanation benefit is process-specific

Category-learning evidence shows explanation can improve broad/abstract hypothesis
generation without improving hypothesis evaluation.

Thus:

```text
ExplanationBenefit_generation
!= ExplanationBenefit_evaluation
```

and:

```text
Explanation != Understanding
```

---

# 66. Explanation quality is not guaranteed by verbosity

Long explanations can be:

```text
circular
irrelevant
confidently wrong
memorized
```

Therefore:

```text
ExplanationLength != ExplanationQuality
```

Understanding evaluation needs structural/causal adequacy and transfer tests.

---

# 67. Prediction is another understanding surface

If a Human model predicts novel cases correctly, that is evidence of useful
structure.

But prediction alone can arise from:

```text
memorized correlation
pattern recognition
black-box heuristic
```

without explanatory access.

Thus:

```text
PredictionAccuracy != CompleteUnderstanding
```

---

# 68. Counterfactual competence is a stronger relational probe

Understanding often requires knowing:

```text
What would change if X changed?
What remains invariant?
Which mechanism is responsible?
```

Therefore:

```text
CounterfactualPerformance_D
```

is a useful understanding surface.

HF8 does not claim it is universally necessary.

---

# 69. Intervention competence is another surface

A Human who can reliably choose an intervention to change outcome Y may possess
important causal/procedural understanding even with limited verbal explanation.

Thus:

```text
InterventionCompetence != VerbalExplanation
```

but both can support understanding evidence.

---

# 70. Transfer is evidence, not definition

HF6/HF7 established transfer as typed.

HF8 retains:

```text
NovelTransfer
```

as evidence that representation extends beyond memorized surface.

But:

```text
TransferSuccess != CompleteUnderstanding
```

because transfer can arise through rule imitation, analogy or accidental overlap.

---

# 71. Understanding requires boundary awareness

A strong world model includes not only:

```text
where it works
```

but also:

```text
where it fails
what it omits
how uncertain it is
```

Thus HF8 includes:

```text
BoundaryKnowledge
```

as a major understanding surface.

---

# 72. Calibration is not understanding itself

A person can accurately know that they do not understand.

Therefore:

```text
UnderstandingCalibration != UnderstandingLevel
```

Good calibration is epistemically valuable but distinct.

---

# 73. Conceptual versus procedural knowledge

Educational studies often distinguish:

```text
ConceptualKnowledge
ProceduralKnowledge
```

HF8 retains this as task-relative evidence, not ontology.

A learner can perform procedure without relational explanation, or explain a
principle while executing poorly.

Thus:

```text
ProceduralSuccess != ConceptualUnderstanding
```

and:

```text
ConceptualExplanation != ProceduralFluency
```

---

# 74. Understanding can be distributed

A Human may understand a system jointly with:

```text
diagram
calculator
simulation
notes
AI
other people
```

Situated understanding/capability can be real without full internalization.

Therefore:

```text
SituatedUnderstandingCapability
!= IndependentInternalUnderstanding
```

---

# 75. External answer access is not internal knowledge

Internet-search experiments show people can answer using external information yet
later have weaker internal learning and inflated self-assessed knowledge.

Thus:

```text
ExternalAnswerAccess != InternalKnowledge
```

---

# 76. Search success is not understanding

A Human can find a correct answer while lacking ability to:

```text
explain
verify
transfer
reconstruct after tool removal
```

Therefore:

```text
SearchSuccess != Understanding
```

---

# 77. External accessibility can distort self-model

Internet-search and partner-knowledge experiments show Human self-assessment can
misattribute externally available knowledge to internal competence.

Thus:

```text
ExternalAccess
can inflate
SelfAssessedInternalKnowledge
```

without equivalent independent ability.

---

# 78. Team knowledge is not individual knowledge

A team can collectively answer questions none of its individual members can answer
alone.

Therefore:

```text
TeamKnowledgeCapability != IndividualKnowledge
```

HF8 treats knowledge distribution relationally, not as identity merger.

---

# 79. Human × AI joint epistemic system

A useful representation is:

```text
HumanRepresentation/Memory
+ AI/Search/Tools
+ Retrieval protocol
+ Source/provenance
+ Verification
+ Division of cognitive labor
= JointEpistemicSystem
```

Its capability can exceed the Human alone.

---

# 80. Joint success does not imply Human understanding

Fisher/Oppenheimer-style partner studies directly show assistance can inflate
expectations of later unaided performance.

Therefore:

```text
JointSuccess != IndividualCompetence
```

and:

```text
AIAssistedAnswer != HumanUnderstanding
```

---

# 81. AI assistance is not deskilling by definition

Recent educational experiments show both:

```text
learning harm under unguarded answer-provision
```

and:

```text
neutral/positive learning under structured/scaffolded designs
```

Therefore:

```text
AIUse != Deskilling
AIUse != LearningGain
```

Tool design and use pattern matter.

---

# 82. The strongest AI falsifier is tool removal

The 2025 high-school math field experiment is especially informative because it
separates:

```text
assisted practice performance
```

from:

```text
unassisted later exam performance
```

Under standard GPT-like assistance, practice improved while unaided exam
performance worsened relative to control; a safeguarded tutor reduced the harm.

Thus:

```text
AssistedPerformance != LearnedCapability
```

---

# 83. AI can become scaffold rather than answer oracle

A learning-oriented tool can instead provide:

```text
hints
questions
feedback
error detection
verification prompts
```

which changes the learner's cognitive work rather than merely supplying final
answers.

HF8 therefore treats AI design as part of the causal learning/understanding system.

---

# 84. Tool effect must specify learning objective

An AI system could improve:

```text
writing quality
critical thinking
factual recall
problem solving
self-regulation
```

differently.

Therefore:

```text
AIEffect_D != AIEffect_E
```

without evidence.

---

# 85. Verification capability is its own epistemic resource

A Human may not independently know every answer but can possess strong ability to:

```text
check source
identify contradiction
recompute result
run experiment
ask discriminating question
```

Thus:

```text
VerificationCapability
```

is distinct from stored knowledge volume.

---

# 86. Knowing how to know

HF8 therefore admits:

```text
EpistemicProcedureKnowledge
```

such as:

```text
how to search
how to verify
how to compare sources
how to falsify
how to recover provenance
```

# 129. Competing models

## M1 — internal-copy representation

```text
world → internal copy → cognition
```

### Strength

Intuitive for some perception/memory tasks.

### Failure

False/counterfactual content, distributed formats, action policies, reconstructive
memory, abstraction.

**Disposition:** reject as complete ontology.

## M2 — propositional-symbolic exclusivity

### Strength

Powerful for explicit reasoning/language.

### Failure

skill, priming, spatial/relational/model evidence, nonverbal competence.

**Disposition:** reject exclusivity; retain propositional representation where
useful.

## M3 — knowledge-as-memory

### Failure

false/obsolete memory and semantic/procedural dissociations.

**Disposition:** reject.

## M4 — knowledge-as-current-correct-answer

### Failure

lucky guess, external lookup, joint assistance, nontransferable answer copying.

**Disposition:** reject.

## M5 — belief-as-confidence

### Failure

confidence/calibration dissociations and remembered-but-rejected content.

**Disposition:** reject.

## M6 — prototype-only concept model

### Failure

exemplar/rule/category-regime evidence.

**Disposition:** retain as local model, reject universal ontology.

## M7 — exemplar-only concept model

### Failure

prototype/rule abstraction evidence.

**Disposition:** retain as local model, reject universal ontology.

## M8 — schema-is-beneficial-knowledge

### Failure

schema-consistent distortion and staleness.

**Disposition:** reject normative/truth identity.

## M9 — mental-models-are-all-representation

### Failure

many representation/action forms do not require explicit possibility models.

**Disposition:** retain reasoning model family, reject universality.

## M10 — understanding-as-explanation

### Failure

skill without explanation; fluent but shallow explanation; process-specific
explanation benefits.

**Disposition:** reject identity.

## M11 — understanding-as-transfer

### Failure

transfer can occur by learned rule/analogy without deep model; some deep local
understanding may be scope-specific.

**Disposition:** transfer is evidence surface, not full definition.

## M12 — external-access-is-knowledge

### Failure

knowledge misattribution and tool-removal results.

**Disposition:** reject for individual internal knowledge; retain joint epistemic
capability concept.
