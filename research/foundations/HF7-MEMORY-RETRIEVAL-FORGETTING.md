# HF7 — Memory, Retention, Forgetting, Consolidation, Retrieval, Interference, Generalization and Transfer

## 0. Status and question

HF6 established that Human history can change future transition functions.

But several cases remained unexplained:

```text
extinguished responses can return
habituated responses can recover
skills remain despite poor recollection
retrieval can improve future remembering
retrieval can also impair competitors
context can change expression of prior learning
false memories can feel real
external reminders can preserve future action
```

HF7 therefore asks:

> **How can past experience remain causally present, how is it made available in
> the present, and what does it mean to remember, forget, retrieve, reconstruct or
> externalize that history?**

HF7 attacks these collapses:

```text
Memory = storage file
Memory = current recall
Forgetting = deletion
Retrieval = read-only access
Recognition = easier recall
Successful recall = true history
Failed recall = no memory
External reminder = internal memory improvement
```

None survives the cross-paradigm evidence.

---

# 1. Memory is not one primitive

HF7 does not retain one unqualified variable:

```text
Memory(H) = M
```

Instead, memory claims must specify at least:

```text
content/domain
induction/encoding history
persistence interval
retrieval cue/conditions
expression channel
confidence/source status
```

A minimum notation is:

```text
MemoryRelation(H, History h, Content/Change c, t, RetrievalConditions r, Domain D)
```

This notation deliberately remains neutral between:

```text
stored representation
changed transition function
learned policy
latent association
procedural skill
priming trace
prospective intention
```

because evidence supports several forms of retained history.

---

# 2. The core HF7 separation

HF7's minimum temporal pipeline is:

```text
Experience / Exposure
        ↓
Encoding / Induction
        ↓
Persistent Change / Retention
        ↓
Consolidation / Reorganization
        ↓
Retrieval Conditions + Cue
        ↓
Retrieval Operation
        ↓
Current Expression
        ↓
Report / Confidence / Action
```

The most important anti-collapse is:

```text
Encoding
!= Retention
!= Retrieval
!= Expression
```

These are different causal roles.

---

# 3. Encoding

HF7 uses `Encoding` for processes during/around an experience that contribute to
later history-dependent availability or performance.

Encoding is not directly observed simply because a stimulus was present.

Thus:

```text
Exposure != EncodingSuccess
```

and:

```text
AttentionAtExposure != GuaranteedMemory
```

Encoding evidence is often retrospective:

```text
later memory differs as a function of earlier processing
```

rather than a direct meter of `stored amount`.

---

# 4. Encoding is not learning completion

HF6 established acquisition/consolidation/retention differences.

HF7 retains:

```text
EncodingEvent
!= CompletedMemoryFormation
```

because later stability/expression may still change after encoding.

Encoding is an input/update phase, not proof that a durable memory exists.

---

# 5. Retention

HF7 uses `Retention_D(c, interval)` for evidence that history-dependent information
or changed capability in domain D remains available across an interval.

Retention is normally inferred from later effects.

It is not direct observation of a static stored object.

Therefore:

```text
RetentionEvidence
!= DirectInspectionOfMemory
```

---

# 6. Availability versus accessibility

A central HF7 distinction is:

```text
Availability
= retained history has some causal potential under suitable conditions

Accessibility
= current retrieval conditions make that history effectively available now
```

Working anti-law:

```text
Availability != Accessibility
```

A failed retrieval test can arise because retained history is unavailable, or
because it is available but inaccessible under current cues/state/competition.

HF7 preserves this uncertainty explicitly.

---

# 7. Expression is another separate layer

Even accessible information may not be expressed through every output channel.

Examples:

```text
priming without recognition
skill without episodic recollection
recognition without source recollection
intention retained but action not triggered
```

Therefore:

```text
Accessibility != Expression_D
```

and:

```text
Expression_D != Expression_E
```

---

# 8. Positive and negative evidence are asymmetric

A specific successful retrieval can strongly support some retained history.

A failed retrieval has many possible causes:

```text
encoding failure
storage/retention loss
weak cue
context mismatch
state mismatch
interference
competition
retrieval strategy failure
response-channel failure
metacognitive threshold
```

Therefore:

```text
SuccessfulRetrieval
and
FailedRetrieval
```

are not symmetric evidence about storage.

Durable rule:

```text
NoCurrentRetrieval != NoRetainedHistory
```

without stronger evidence.

---

# 9. Memory evidence must be task-typed

HF7 distinguishes at least:

```text
FreeRecall
CuedRecall
Recognition
SourceMemory
TemporalOrderMemory
Recollection
Familiarity
Priming
SkillPerformance
ConditionedResponse
ProspectiveMemory
Relearning/Savings
```

A result on one task cannot automatically become a global memory claim.

```text
MemoryTask_D != MemoryTask_E
```

---

# 10. Retrieval is not passive readout

The simplest storage model says:

```text
Memory file exists
→ retrieval reads file
```

Retrieval-practice experiments falsify the passive-read assumption.

Retrieving information can change its later retention.

Therefore:

```text
Retrieval != PassiveMeasurement
```

and:

```text
MeasurementOfMemory
can become
InterventionOnMemory
```

This is the memory analogue of HF0's reflexivity rule.

---

# 11. Testing effect

Retrieval practice can produce better delayed retention than additional study in
some paradigms even when immediate study performance appears stronger.

Thus:

```text
ImmediateFluency
!= LongTermRetention
```

and:

```text
Restudy
!= RetrievalPractice
```

as learning operations.

The practical implication is that being tested can change what a later test is
trying to assess.

---

# 12. Retrieval can also impair related material

Retrieval-induced forgetting demonstrates another direction of effect.

Selective retrieval of target items can:

```text
enhance target accessibility
+
reduce later recall of related competitors
```

under appropriate conditions.

Therefore:

```text
RetrievalBenefit_A
can coexist with
RetrievalCost_B
```

A memory intervention should not be modeled only as additive strengthening.

---

# 13. Forgetting must be qualifier-required

HF7 rejects one process:

```text
Forgetting = stored trace disappears
```

Instead `Forgetting` is first an observation:

> later expression is lower/less accurate/less available than at an earlier or
> comparison point.

Possible mechanisms include:

```text
encoding was weak from the start
storage/trace degradation
retrieval failure
cue mismatch
context/state mismatch
interference
competition/inhibition
transformation/update
response threshold change
```

Thus:

```text
ForgettingBehavior != PhysicalDeletion
```

---

# 14. ForgettingProfile

HF7 recommends:

```text
ForgettingProfile_D = {
  task / expression channel,
  retention interval,
  cue conditions,
  context/state,
  interference history,
  recognition/recall difference,
  savings/relearning,
  reinstatement/recovery,
  confidence,
  mechanism confidence
}
```

This prevents one forgetting curve from becoming one mechanism.

---

# 15. Forgetting can be access failure

Context/state effects show that a memory may be harder to retrieve in one state
and easier in another.

Therefore:

```text
LowAccessibilityNow
!= StorageLoss
```

The distinction is strongest when changing cues/state recovers performance.

---

# 16. But context dependence is not a universal law

The classic land/underwater experiment reported same-context recall benefits.
A later close replication did not reproduce the effect.

HF7 therefore retains:

```text
Retrieval can be context-sensitive
```

while rejecting:

```text
PhysicalContextMatch always improves memory
```

Replication status is part of the ontology discipline.

---

# 17. State-dependent retrieval

Matching internal state between encoding and retrieval can improve some recall
under some pharmacological/mood paradigms.

This supports:

```text
RetrievalConditions include InternalState
```

but does not establish that memory is stored `inside` one state.

Therefore:

```text
StateDependentExpression
!= StateSpecificStorage
```

without additional evidence.

---

# 18. Interference

HF7 uses `Interference` broadly for cases in which one history/representation
reduces access to or expression of another.

Typed forms include:

```text
ProactiveInterference
RetroactiveInterference
RetrievalInducedInterference
OutputInterference
CueCompetition
```

No one mechanism is assumed across all forms.

---

# 19. Interference is not overwriting by default

If learning B reduces recall of A, possible explanations include:

```text
overwrite/storage change
competition
context drift
retrieval inhibition
cue overload
strategy change
```

Therefore:

```text
InterferenceEffect != ProvenOverwriting
```

The mechanism must be independently constrained.

---

# 20. Savings/relearning exposes hidden persistence

A learned behavior can appear to return near baseline yet be relearned faster than
initial acquisition.

Thus:

```text
CurrentPerformanceBaseline
!= NoResidualHistory
```

Savings is evidence that current overt performance can underestimate retained
change.

It does not identify a specific storage mechanism by itself.

---

# 21. Amnesia breaks the unitary-memory model

Severe anterograde amnesia can impair:

```text
free recall
recognition
recollection of learning episode
```

while leaving substantial:

```text
skill learning
priming
```

intact under some tasks.

Therefore:

```text
ExplicitMemory != ProceduralSkillMemory
```

and:

```text
ExplicitMemory != Priming
```

This is a structural dissociation, not merely a difference in difficulty.

---

# 22. Memory systems language is useful but provisional

HF7 permits terms such as:

```text
declarative / explicit
episodic
semantic
procedural / skill
priming
conditioning
```

as research projections.

It does not freeze one taxonomic tree as the Human ontology.

Different tasks and lesion patterns motivate partially distinct systems/processes,
but boundaries and mechanisms vary.

Thus:

```text
UsefulMemoryTaxonomy != FinalMemoryOntology
```

---

# 23. Episodic recollection is not all remembering

Episodic recollection involves retrieval of event-specific/contextual information.

A Human can show history-dependent performance without episodic recollection.

Therefore:

```text
Memory != EpisodicRecollection
```

This is one of HF7's most important Human anti-collapses.

---

# 24. Recognition is not simply recall with more help

Recognition asks whether a presented item is judged as previously encountered.

Recall requires generation/recovery without the identical target presentation.

But recognition itself can draw on different processes such as:

```text
recollection
familiarity
```

Therefore:

```text
Recognition != Recall
```

and:

```text
Recognition != Recollection
```

---

# 25. Familiarity and recollection

HF7 uses:

```text
Recollection
= recovery of qualitative/contextual information about a prior encounter

Familiarity
= experienced/judged prior-occurrence strength without equivalent contextual
  recovery
```

as working process constructs.

They can show different forgetting or aging patterns under some paradigms.

Therefore:

```text
Familiarity != Recollection
```

HF7 does not declare one dual-process model final.

---

# 26. Content memory and source memory are different

A Human may remember:

```text
statement X
```

while failing to remember:

```text
who said X
when X occurred
whether X was imagined/read/heard
```

Therefore:

```text
ContentMemory != SourceMemory
```

and:

```text
ItemRecognition != ContextRecollection
```

This becomes central to truth and belief in the next foundation.

---

# 27. Temporal-order memory is another distinct relation

Remembering that two events occurred does not guarantee accurate memory of their
order.

Aging studies can show temporal-order deficits despite relatively preserved item
recognition.

Therefore:

```text
ItemMemory != TemporalOrderMemory
```

---

# 28. Current confidence is not memory truth

A person can confidently recognize/recollect information that was not presented.

Therefore:

```text
Confidence != Veridicality
```

HF3 already separated confidence from accuracy.
HF7 extends that rule to remembered history.

---

# 29. False memory

False-memory paradigms show that semantically related but nonpresented items can be
recalled or recognized, sometimes with subjective recollective experience.

Therefore retrieval cannot be modeled as exact literal playback.

HF7 retains:

```text
Retrieval = constructive / cue-driven operation
```

as a strong methodological constraint.

But `constructive` does not mean `arbitrary`.

---

# 30. Constructive memory is not unreliable memory by definition

A system can reconstruct useful history from partial cues and structured prior
knowledge while remaining generally accurate.

Thus:

```text
Reconstructive != False
```

and:

```text
FalseMemoryExists
!= AllMemoryUnreliable
```

The relevant question is error conditions and evidence channels.

---

# 31. False recollection is not lying

A Human can sincerely report a memory that does not correspond to the experimental
history.

Therefore:

```text
FalseRecall != Deception
```

without evidence of intentional misreporting.

HF7 separates:

```text
subjective mnemonic state
historical truth
communicative honesty
```

as three different dimensions.

---

# 32. Laboratory false memory has a domain boundary

Semantic word-list false-memory paradigms establish reconstructive error under
controlled conditions.

They do not directly establish error rates or mechanisms for:

```text
childhood autobiographical memory
trauma memory
forensic testimony
```

Therefore:

```text
DRMFalseMemoryEffect
!= UniversalAutobiographicalFalseMemoryModel
```

without external validation.

---

# 33. Retrieval can update memory

Reminder-driven experiments show that reactivating an earlier episode before new
learning can change later report of the earlier episode.

Thus:

```text
Retrieval / Reactivation
can become
UpdateOpportunity
```

This further defeats read-only storage models.

---

# 34. Reconsolidation is mechanism-level, not definition-level

One interpretation of reminder-dependent updating is reconsolidation:

```text
reactivation → lability → restabilization/update
```

But human behavioral patterns can sometimes be captured by alternative temporal-
context/retrieval models.

Therefore:

```text
BehavioralUpdating
!= UniqueProofOfReconsolidation
```

HF7 retains reconsolidation as a competing mechanism family.

---

# 35. Memory can contain competing histories

Extinction return provides a particularly useful abstraction.

One cue can support:

```text
earlier CS→US relation
later extinction / CS→no-US relation
```

with current expression depending on context/time/history.

Thus:

```text
NewLearning
need not equal
OldLearningErasure
```

A Human can retain competing histories whose retrieval weights change.

---

# 36. Expression competition is not proof of storage competition

If one memory dominates behavior, the competitor may still remain latent.

Therefore:

```text
DominantExpression_A
!= AbsenceOfMemory_B
```

Return-of-response effects are direct pressure on this distinction.

---

# 37. Generalization

HF7 uses `Generalization` for a retained history affecting novel but related
inputs/contexts.

Typed dimensions include:

```text
StimulusGeneralization
ContextGeneralization
ResponseGeneralization
ConceptualGeneralization
TaskGeneralization
```

Thus:

```text
Generalization_D != Generalization_E
```

---

# 38. Generalization is not transfer in every usage

HF6 used transfer broadly for cross-condition performance consequences.

HF7 uses:

```text
Generalization
= how learned/remembered relation extends across representational/cue similarity

Transfer
= effect of prior learning/memory on a materially different task/condition
```

They overlap but are not identical.

```text
Generalization != Transfer
```

as a useful working distinction.

---

# 39. Transfer depends on retrieval as well as learning

A retained skill may fail transfer because:

```text
representation too specific
cue structure changes
retrieval does not activate relevant relation
policy is context-bound
new task requires missing components
```

Therefore:

```text
TransferFailure
!= NoRetention
```

This clarifies an HF6 residual.

---

# 40. Memory specificity can be useful

General memory is not always better.

Specificity can reduce inappropriate transfer and interference.

Therefore:

```text
MoreGeneralization != AlwaysBetterMemory
```

Normative evaluation depends on task and error costs.

---

# 41. Prospective memory

Prospective memory concerns remembering to execute an intention in the future.

A minimum structure is:

```text
Intention content
+ retention interval
+ future cue/time condition
+ cue detection / monitoring
+ intention retrieval
+ action initiation
```

Thus:

```text
RememberWhat != RememberToAct
```

---

# 42. Prospective and retrospective components

A prospective-memory failure can occur because:

```text
intention was forgotten
cue was missed
cue was detected but intention not retrieved
intention retrieved but action blocked
implementation was ambiguous
```

Therefore:

```text
ProspectiveMemoryFailure
!= RetrospectiveContentLoss
```

without decomposition.

---

# 43. Implementation intentions change retrieval architecture

An if-then implementation intention:

```text
If cue X occurs → execute action Y
```

can improve prospective performance without changing the final goal's value.

HF4 treated this as action implementation.
HF7 now treats it also as retrieval-cue engineering.

Thus:

```text
ImplementationPolicy
can become
MemoryRetrievalSupport
```

across foundations.

---

# 44. External memory

Humans routinely move memory work into the environment:

```text
notes
calendar
alarm
checklist
bookmark
search history
AI memory
```

HF7 calls these `ExternalMemorySupports` when they preserve or cue history relevant
to later action.

They are part of the situated memory system without becoming biological memory.

---

# 45. Cognitive offloading

Working definition:

```text
CognitiveOffloading
= action that changes the external environment or tool state so that later task
  success requires less internal maintenance/retrieval demand
```

This can increase joint task success.

Therefore:

```text
ExternalOffloading
can increase
SituatedMemoryCapability
```

---

# 46. Offloading is not internal memory gain

A reminder can improve remembering-to-act while leaving internal retrospective
memory unchanged.

Therefore:

```text
ReminderBenefit
!= InternalRetentionGain
```

and:

```text
JointMemoryCapability
!= IndependentInternalMemoryCapability
```

This directly parallels HF1/HF6 capability distinctions.

---

# 47. Offloading is not deskilling by default

External support can:

```text
reduce internal rehearsal
reduce forgetting consequences
increase task coverage
free resources for reasoning
create reliable retrieval cues
```

Its long-term effect on internal memory can be positive, negative or neutral.

Therefore:

```text
Offloading != Deskilling
```

without longitudinal/tool-removal evidence.

---

# 48. Reminder use depends on metacognition

People choose reminders partly based on confidence in unaided memory and reminder
cost.

Thus:

```text
MemorySupportChoice
depends on
Metamemory / confidence
```

HF3 confidence/metacognition therefore directly modulates HF7 external-memory
architecture.

---

# 49. Metamemory is not memory ability

A person can be:

```text
accurate memory + low confidence
weak memory + high confidence
```

and therefore over- or under-use reminders.

So:

```text
MetamemoryConfidence != MemoryPerformance
```

HF7 treats metacognitive calibration as a separate control layer.

---

# 50. External memory creates reliability dependencies

If later remembering depends on:

```text
calendar exists
notification fires
account accessible
AI retains context
network available
```

then situated memory capability includes infrastructure reliability.

Thus:

```text
ExternalMemoryCapability
= relation(Human, Tool, Cue, Availability, Access, Context)
```

not merely `Human memory + device`.

---

# 51. External memory changes failure modes

Internal failure modes:

```text
forgetting
interference
retrieval failure
```

Externalized systems add:

```text
device loss
corruption
permission failure
notification overload
wrong retrieval cue
stale record
model hallucination
```

Therefore offloading reduces some risks while adding others.

```text
Externalization != RiskElimination
```

---

# 52. Source and provenance become more important under offloading

When memory is externalized, later retrieval should preserve:

```text
what was stored
when
by whom
from which source
whether edited
confidence / verification
```

Otherwise successful retrieval can amplify stale or false content.

This is one route from HF7 into the HF8 knowledge/belief boundary.

---

# 53. Aging is process-specific

HF6 rejected uniform decline.
HF7 now shows why specifically for memory.

Aging effects can differ across:

```text
free recall
cued recall
recognition
recollection
familiarity
temporal-order memory
prospective memory
source memory
```

Therefore:

```text
AgingMemoryEffect_D != AgingMemoryEffect_E
```

---

# 54. Recognition can be less impaired than recall/order

Some aging experiments show relatively preserved item recognition alongside
larger deficits in temporal order or spontaneous recall.

This supports:

```text
RetrievalSupport matters
```

without proving all age-related memory change is retrieval-only.

---

# 55. Retrieval support is not restoration of storage

Recognition cues, implementation intentions or reminders can improve performance.

That demonstrates performance is cue/control sensitive.

It does not by itself establish that underlying retained content was fully intact.

Therefore:

```text
CueBenefit != ProofOfPerfectStorage
```

HF7 preserves competing storage/retrieval contributions.

---

# 56. Memory age effects can involve encoding too

Reduced later recollection can arise from differences during encoding as well as
retrieval.

Therefore:

```text
AgeRelatedRetrievalDeficit
```

should not become the universal explanation for age-related memory differences.

Typed task and process evidence is required.

---

# 57. Memory and identity

HF1 separated Human identity from autobiographical memory.

HF7 strengthens:

```text
AutobiographicalMemoryContinuity
!= HumanIndividualContinuity
```

A Human can persist despite profound episodic-memory loss.

Conversely autobiographical memory strongly contributes to narrative/self models
without constituting the organism.

---

# 58. Memory and experience

HF2 established:

```text
Experience != LaterRecall
```

HF7 explains why later recall is downstream of:

```text
encoding
retention
retrieval cue
interference
report
```

Therefore:

```text
NoRecall(t2)
!= NoExperience(t1)
```

remains a core anti-law.

---

# 59. Memory and attention

HF3 attention can affect encoding/retrieval, but:

```text
Attention != Memory
```

Some attended information is not retained.
Some history-dependent effects occur without explicit attention/recollection.

Thus:

```text
Attended != Remembered
Remembered != PreviouslyAttendedConsciously
```

without task-specific evidence.

---

# 60. Memory and working memory

HF3 WorkingMemory concerns currently maintained/manipulated information.
HF7 memory largely concerns history-dependent persistence beyond the current
maintenance episode.

Therefore:

```text
WorkingMemory != LongTermMemory
```

but working-memory operations can participate in encoding and retrieval.

No one-box memory model is retained.

---

# 61. Memory and goal/self-regulation

HF4 prospective goals require retained intentions.

HF7 provides the memory side:

```text
Goal formed now
→ intention must survive delay
→ cue must retrieve it later
→ action system must execute
```

Thus self-regulation failure can be a memory/retrieval failure without low goal
value.

---

# 62. Memory and bodily state

HF5 showed internal state alters cognition/action.
HF7 adds:

```text
State can alter retrieval accessibility
```

while memory itself can alter bodily regulation through learned predictions and
conditioned responses.

So:

```text
Memory ↔ Regulation
```

is bidirectional across timescales.

---

# 63. Memory and adaptation

HF6's `Theta` can include memory-like persistent structures.

HF7 clarifies that not every persistent adaptation should be called memory in the
same sense.

Working distinction:

```text
Adaptation
= persistent change in future response

Memory
= persistent history-dependent change represented/inferred through retained
  information, associations, policies or performance dispositions
```

The boundaries overlap but are not identical.

---

# 64. Memory does not need one storage place

Different retained history can be implemented through distributed neural/body/
behavioral structures.

HF7 therefore rejects:

```text
Memory = one anatomical store
```

as a foundation assumption.

`Storage` is a functional role unless mechanism is specified.

---

# 65. Storage is a dangerous metaphor

Computer vocabulary suggests:

```text
write bytes
keep bytes unchanged
read bytes
```

Human memory violates each step in many contexts:

```text
encoding is selective
retention can reorganize
retrieval is cue-dependent
retrieval can update
expression can reconstruct
```

Therefore HF7 uses `retention/persistent availability` when possible and reserves
`storage` for a declared model.

---

# 66. Memory trace is also mechanism-relative

`Trace` can mean:

```text
synaptic pattern
neural ensemble change
behavioral disposition
model variable
```

HF7 does not retain a free primitive `memory trace`.

Use:

```text
Trace_M
```

only when mechanism M is defined.

---

# 67. Consolidation family

HF7 separates:

```text
Stabilization
SynapticConsolidation
SystemsConsolidation
OfflineReorganization
Reconsolidation / Updating
```

as theoretical/mechanistic families.

HF7 does not assume one process applies identically to every memory type.

---

# 68. Consolidation is inferred from change across time/interference

Evidence can include:

```text
reduced interference vulnerability
post-delay stabilization
brain/physiology change
sleep-dependent change
```

but:

```text
TimePassed != Consolidation
```

and:

```text
SleepOccurred != ConsolidationProof
```

without a comparative design.

---

# 69. Retrieval is cue-conditioned

A useful abstraction is:

```text
RetrievedContent_t
= R(
    RetainedHistory,
    Cue_t,
    Context_t,
    InternalState_t,
    Goal_t,
    Competition_t,
    RetrievalPolicy_t
  )
```

This is structural, not one fitted equation.

It encodes the key fact:

```text
same retained history
+ different retrieval conditions
→ different current expression
```

---

# 70. Retrieval is selective

Not all retained history can or should become active at once.

Retrieval solves a selection problem among candidate memories.

This connects to HF3:

```text
MemoryRetrieval
requires selection/priority mechanisms
```

and helps explain interference/competition.

---

# 71. Retrieval is reconstructive

Current output can combine:

```text
retained information
current cue
semantic associations
schemas/priors
source inference
current goals
```

Thus current remembering is an event, not simply the reappearance of the past.

HF7 therefore retains:

```text
MemoryContentAtRetrieval
can differ from
OriginalExperienceContent
```

without concluding total arbitrariness.

---

# 72. Current memory report is an inference target

Observed report:

```text
“I remember X”
```

is evidence about:

```text
current subjective recollection
confidence
retrieved content
```

but historical truth requires additional evidence.

Thus:

```text
MemoryReport != HistoricalEvent
```

This is an authority boundary, not a reason to dismiss first-person testimony.

# 102. Competing memory models

HF7 pressure-tests several broad families.

## M1 — static storage/readout model

```text
encode file → store unchanged → retrieve copy
```

### Strength

Useful engineering metaphor and local approximation.

### Failure

Retrieval effects, updating, false memory, cue dependence, extinction return.

**Disposition:** reject as full Human memory ontology.

## M2 — unitary strength model

```text
one memory strength determines all tasks
```

### Failure

Recall/recognition/priming/skill/source/order/prospective dissociations.

**Disposition:** reject globally; retain scoped strength variables where validated.

## M3 — availability/access model

```text
retention and current accessibility are distinct
```

### Strength

Explains cue/state/context recovery and latent history.

### Failure

Still underspecifies constructive retrieval and memory-system differences.

**Disposition:** retain core distinction.

## M4 — multiple-systems/process model

### Strength

Explains amnesia dissociations and task-specific effects.

### Failure

Exact taxonomy/boundaries remain debated and task-sensitive.

**Disposition:** retain pluralism, not one final tree.

## M5 — reconstructive/inferential model

### Strength

Explains false memory, source errors, updating and semantic influence.

### Failure

Can become too broad if used to deny stable retention/veridical memory.

**Disposition:** retain retrieval-as-construction constraint, not total skepticism.

## M6 — reconsolidation/update model

### Strength

Explains reminder-dependent post-reactivation change under some conditions.

### Failure

Behavioral results can admit competing temporal-context models.

**Disposition:** mechanism rival, not ontology authority.

## M7 — distributed/external memory model

### Strength

Explains situated capability with reminders/tools.

### Failure

Can blur internal memory, tool state and provenance if boundaries are ignored.

**Disposition:** retain dimension-specific joint-system model.

# 114. HF7 synthesis

HF7 began from:

```text
How can history remain causally present when not currently expressed?
```

The surviving answer is not one hidden file.

It is a layered relation:

```text
history
→ encoding
→ persistent change/availability
→ cue/context/state-dependent retrieval
→ constructive expression
```

with multiple memory forms and output channels.

Retrieval itself can alter future memory, and forgetting-like behavior can reflect
loss, access failure, interference or reweighting.

The deepest compression is:

```text
Memory is not the past stored unchanged.
Memory is the Human system's history-dependent capacity to make parts and effects
of the past available for present/future cognition and action under particular
retrieval conditions.
```

But once content is retrieved, a different question immediately appears:

> **What does that representation mean, when should it be believed, when does it
> count as knowledge, and when does it amount to understanding?**

That is the HF8 representation/knowledge boundary.
