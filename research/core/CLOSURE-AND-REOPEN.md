# Human Closure and Reopen Rules

## Current closure state

```text
HF0–HF23 = local frozen Foundation closure
WholeHumanFoundationExhaustion = NOT ESTABLISHED
HF24 = UNKNOWN / not admitted
FoundationReopenCondition(HF0–HF23) = false

HD11–HD16 = STAGE COMPLETE research history
NextHumanDeepRoute = UNKNOWN
WholeHumanExhaustion = NOT CLAIMED

HOC0–HOC10 = frozen
HOC11 = UNKNOWN / not admitted
WholeHumanOperationalClosure = NOT ESTABLISHED
```

Local closure is not whole-domain exhaustion.

## Foundation reopen gate

Reopen a frozen HF only for a concrete, repeated foundation-level failure such as:

1. repeated cross-domain category error;
2. incompatible strong evidence;
3. repeated missing distinction;
4. contradiction across frozen rounds;
5. repeated unusable consumer mapping caused at Foundation level;
6. normative-authority leak.

New terminology, a single paper, one edge case, neatness or taxonomy pressure are insufficient.

## Deep candidate reopen gate

A candidate-specific HF24 closure may reopen only if a reusable process/relation remains necessary after all neighboring owners are restored **and** repeated peer deletion harm persists across materially different regimes. Selective dissociation, one lesion network, one computation or one domain-specific effect is insufficient.

## HOC reopen/admission gate

Reopen a frozen HOC only for a concrete operational counterexample: collapsed distinct decision objects, a falsified forbidden inference, a stable high-value use case unrepresentable by current composition, a new Human–Agent regime that changes the operational object, or systematic evidence-grammar misclassification.

A new HOC additionally requires recurring practical value, bounded target/context/time/support, evidence/update/expiry/uncertainty, forbidden inferences, deletion harm, and benefit exceeding privacy/governance cost.

## Stop condition

This repair does not select `HF24`, `HOC11` or any new route. Numeric succession and residual maps have no roadmap authority.
