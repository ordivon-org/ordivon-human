# HD13-A — Current-Use / Term Separation / Hidden-Assumption Inventory

## 0. Entry rule

```text
HD13Admission != HF24Admission
```

A does not select a numerical-cognition theory.

It asks:

> When a paper, assessment or engineering system says `number`, `number sense`, `quantity`, `magnitude`, `counting`, `arithmetic` or `numeracy`, what exact target, representation and task is actually present?

---

# 1. World-side quantity is not Human numerical cognition

World-side targets may include:

```text
SetCardinality(S)
OrderRelation(a,b)
ContinuousMagnitude_D(x)
Ratio(a,b)
Proportion(part,whole)
ExactEquality(S,T)
MathematicalRelation(P)
```

Human-side states concern perception, representation, memory, inference, action and symbolic use of such relations.

Therefore:

```text
ObjectiveCardinality != HumanCardinalityRepresentation
MathematicalNumber != NumberWord
MathematicalTruth != HumanCalculationPerformance
```

World retains objective quantity/mathematical truth.

---

# 2. `NumericalCognition` is an umbrella

Current usage covers materially different questions:

```text
How many visible items?
Which set is more numerous?
What exact number word labels this set?
Which numeral is larger?
What comes after seven?
Can this set be counted exactly?
Can two sets be matched one-to-one?
What is 7×8?
Can an approximate sum be chosen without counting?
Which fraction/ratio is larger?
Where should 37 be placed on a line?
Can a Human detect that three objects are present immediately?
```

These are not one target.

Retain:

```text
NumericalCognition
= heterogeneous research umbrella
!= one primitive NumberSense
```

---

# 3. Quantity

`Quantity_D` is the amount/value of a declared dimension.

It may be:

```text
discrete item count
length
area
volume
time
mass
intensity
probability
ratio
```

Therefore:

```text
Quantity != NumberByDefinition
```

A quantity can be non-numerical in Human representation and can concern continuous dimensions.

---

# 4. Magnitude

`Magnitude_D` is an ordered amount/extent on a declared dimension.

Examples:

```text
larger area
longer duration
greater loudness
more numerous set
larger numerical value
```

Thus:

```text
Magnitude
= dimension-qualified order/extent family
!= NumerosityByDefinition
```

A generalized magnitude hypothesis is a theory about shared processing, not a terminological truth.

---

# 5. Numerosity

Use:

```text
Numerosity(S)
= number of individuated discrete elements in set/ensemble S
```

for the target quantity.

Human numerosity judgment depends on segmentation/individuation and can be influenced by non-numerical visual properties.

2024/2025 developmental evidence shows numerosity and area judgments have partly different trajectories while both dimensions can interfere with each other.

Therefore:

```text
Numerosity != ContinuousMagnitude
```

and:

```text
NumerosityJudgment
!= PureVisualFeatureReadout
```

---

Dot-array tasks can vary:


These variables can covary with numerosity.

Therefore every nonsymbolic numerosity claim must state visual-feature controls.

```text
DotArrayAccuracy
!= NumerosityRepresentationOnly
```

# 9. Number word

A number word is a linguistic/symbolic form in a stabilized symbolic system.

Examples:

```text
“three”
“twenty”
```

HF23 owns the symbolic system.

```text
NumberWord != NumberConcept
```

Bilingual development shows children can learn mappings for small number words separately in each language while broader counting principles may generalize differently.

Thus form-to-concept mapping must be explicit.

---

# 10. Numeral / notation

A numeral is an external symbolic form such as:

```text
3
III
三
```

or a structured mathematical notation.

HF23 owns reusable symbolic-system structure.

```text
Numeral != Number
NumeralIdentity != NumericalMagnitude
```

Number-line evidence shows digit identity itself can affect placement even when target numerical magnitudes are close, so symbolic tasks are not transparent magnitude readouts.

---

# 11. Cardinality

`Cardinality` asks:

```text
How many members are in this set?
```

For exact natural-number concepts, cardinality connects set size to exact number.

Developmentally:

```text
reciting a count list
!= understanding cardinality
```

Children can count before reliably understanding that the final number word gives the set size.

---

# 12. Cardinal principle

Use:

```text
CardinalPrincipleKnowledge
= understanding that a correctly completed count maps the final count word
  to the exact cardinality of the counted set
```

But even this must be measured carefully: recent error analyses indicate component counting principles can emerge gradually and task implementation can lag conceptual knowledge.

Thus:

```text
GiveNFailure
!= NoCardinalityKnowledgeByDefinition
```

---

# 13. Successor relation

For exact natural numbers:

```text
Successor(n) = n + 1
```

as mathematical content.

Human understanding that adding one item corresponds to the next count word is an exact-number conceptual relation.

Children can know portions of a count sequence without having generalized this relation across all known number words.

Therefore:

```text
CountListKnowledge
!= GeneralSuccessorKnowledge
```

---

# 14. Equinumerosity / exact equality

Use:

```text
Equinumerous(S,T)
= S and T have the same exact cardinality
```

One-to-one correspondence can establish exact equality without requiring an internal verbal label for the cardinality.

Thus:

```text
ExactEqualityRelation
!= NumberNaming
```

and:

```text
ExactMatching
!= ExactNumberWordKnowledge
```

---

# 15. Ordinality

`Ordinality` concerns ordered position or greater/less numerical relation.

Examples:

```text
third
before/after in count sequence
7 > 5
```

It is not the same target as cardinality.

```text
Cardinality != Ordinality
```

Infant/child evidence shows numerical order competence can have its own developmental trajectory.

---

# 16. Magnitude comparison vs order judgment

Both tasks can produce a numerical distance effect.

Yet first-grade evidence found individual differences in symbolic magnitude comparison and order judgment, including their distance effects, need not correlate.

Therefore:

```text
NumericalMagnitudeProcessing
!= NumericalOrderProcessingByDefinition
```

# 19. One-to-one correspondence

`OneToOneCorrespondence(S,T)` is a matching relation between elements of two sets.

Piraha matching evidence pressures the collapse:

```text
ExactSetMatching
```

```text
OneToOneMatchingCapability
```

# 20. Enumeration

`Enumeration` is the task/output family for determining/reporting set size.

It can be implemented by:

```text

```

Therefore:

```text
Enumeration != Counting
```

# 21. Subitizing

Operationally:

```text
Subitizing
= rapid, low-slope, high-accuracy enumeration of small sets
  under a declared paradigm
```

Do not define the mechanism into the term.

Classic lesion and modern neuropsychological evidence distinguishes subitizing-range enumeration from larger-set counting.

Thus:

```text
Subitizing != FastCountingByDefinition
```

---

# 22. Subitizing is not ANS by definition

One model treats small-number performance as the high-precision end of approximate estimation.

Another treats it as parallel object individuation with a limited capacity.

Human lesion/dual-task evidence supports substantial object-individuation involvement: subitizing capacity shares resources with multiple-object tracking, and lesions affecting small-set enumeration differ from large-set counting lesions.

Therefore:

```text
Subitizing != ANSByDefinition
```

and:

```text
SubitizingPerformance
can depend on HF20 object individuation / attention machinery.
```

---

# 23. Object Tracking System / parallel individuation

`OTS` / `parallel individuation` is a model family for maintaining/indexing a small number of distinct objects.

It is not synonymous with exact number representation.

```text
ObjectIndividuation
!= ExactNumberConcept
```

and:

```text
OTSContributionToCardinalityLearning
!= OTSOwnsNumberConcept
```

Longitudinal work finds both OTS- and ANS-related measures can predict early cardinal learning, rejecting simple single-system entry assumptions.

---

# 24. Approximate Number System / ANS

A-round neutral definition:

```text
ANS
= theory/model family positing noisy, ratio-sensitive representation
  of nonsymbolic numerosity over a broad range
```

It is a model, not a synonym for:

```text
numerosity
quantity
number
number concept
mathematics
```

Thus:

```text
ANS != NumericalCognitionTotality
```

# 25. Exactness is not symbolic format

`Exact` means a relation/value is represented or determined without a tolerance band around neighboring integer possibilities for the declared task.

`Symbolic` means information is carried through a conventional sign system.

Therefore:

```text
Exactness != Symbolicness
```

Counterexamples:

```text
one-to-one visible matching can be exact without number words
symbolic estimation can be approximate
```

---

Use cautiously:

```text
ExactNumberRepresentation
= representation supporting exact cardinal/ordinal/equality relations
  for a declared integer domain
```

```text
OneCorrectExactResponse
!= StableExactNumberConcept
```

# 27. Approximate number

Use:

```text
ApproximateNumericalEstimate
```

# 29. Nonsymbolic quantity

Nonsymbolic means the target is presented without a conventional exact numerical symbol.

Examples:


It does **not** mean approximate by definition.

```text
Nonsymbolic != ApproximateByDefinition
```

Visible one-to-one matching can support exact performance.

Operationally:


